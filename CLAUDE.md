# hideout-web

Frontend for Hideout: invite-only voice and text rooms for Steam players. This repo is a React SPA. The API, database schema, and API contract live in a separate repo (`hideout-api`). This repo never defines backend behavior; it consumes the contract.

## Stack

- React 18 + Vite + TypeScript (strict)
- **shadcn/ui** components (Radix UI primitives + Tailwind CSS v4), copied into `src/components/ui` via the shadcn CLI
- `lucide-react` icons, `sonner` toasts, `class-variance-authority` + `tailwind-merge` (`cn()`) for variants
- `react-hook-form` + `@hookform/resolvers/zod` with the shadcn form components
- **TanStack Router** with file-based routing (`@tanstack/router-plugin/vite`)
- TanStack Query for all server data; Zustand for UI-only state that outlives a route (e.g. the voice session)
- `openapi-typescript` + `openapi-fetch` for a typed API client generated from hideout-api's contract
- `@supabase/supabase-js` for reading messages and live updates (read-only)
- `livekit-client` + `@livekit/components-react` for voice (hooks only; UI is built with shadcn components)
- Zod for form schemas, search params, and Realtime payload validation
- Vitest + React Testing Library + MSW; Playwright for e2e

## Commands

```bash
npm install
npm run dev               # Vite on :5173, proxies /api to localhost:3001; regenerates the route tree
npm run typecheck
npm run lint
npm run test
npm run test:e2e          # needs hideout-api running locally
npm run build
npm run gen:api           # regenerate src/lib/api/schema.d.ts from hideout-api's openapi.json
npx shadcn@latest add <component>   # add a shadcn component to src/components/ui
```

`gen:api` reads `API_CONTRACT_URL` (default `http://localhost:3001/api/openapi.json`). In CI it points at the deployed API's contract or a pinned file from hideout-api.

Done means: `npm run typecheck && npm run lint && npm run test` pass, and `npm run build` succeeds.

## shadcn/ui rules

- **Components are owned code.** `src/components/ui/*` is ours, added with `npx shadcn@latest add <name>`. Check the shadcn registry before building a primitive yourself. Never hand-copy components from the docs site; use the CLI so `components.json` aliases and styles stay consistent.
- **Change variants, not call sites.** Recurring looks (e.g. a `ghost-muted` button, a compact `Avatar` size) become new `cva` variants in the ui component. One-off `className` overrides are for layout (margin, width, grid placement), not for restyling a component.
- **Design tokens live in `src/index.css`** as CSS variables (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, `--ring`, `--sidebar-*`, ...) mapped into Tailwind with `@theme inline`. Use semantic classes (`bg-background`, `text-muted-foreground`, `border-border`). No raw hex/oklch values or arbitrary colors (`bg-[#...]`) in components.
- **Always merge classes with `cn()`** from `lib/utils.ts`, and accept a `className` prop on composed components.
- **Dark mode:** class-based (`.dark` on `<html>`) via the `ThemeProvider` in `components/` (light, dark, system; persisted in localStorage). Every screen must work in both themes; use tokens so you rarely need `dark:` variants.
- **Layout:** the app shell uses the shadcn `Sidebar` (room rail + channel list). The member list is a right-hand panel on desktop and a `Sheet` on mobile. Use Tailwind responsive prefixes and the `useIsMobile` hook; breakpoint for drawers is `md`.
- **Which component for what:**
  - Overlays: `Dialog` (create room, invite), `AlertDialog` (destructive confirmations: delete room, remove member), `Sheet` (mobile panels), `DropdownMenu`, `Popover`, `Tooltip`, `ContextMenu` (message actions).
  - Feedback: `Skeleton` for loading, `Alert` for persistent problems (connection lost, mic blocked), `sonner` `toast()` for transient results (invite copied, message failed).
  - Content: `ScrollArea` for channel and member lists, `Avatar` with fallback initials, `Badge` for roles, `Command` for quick switcher/search.
- **Forms:** `react-hook-form` + `zodResolver` with the shadcn form/field components, so labels, descriptions, and errors are wired with the right `aria-*` attributes. Map API 422 errors to fields with `form.setError`.
- **Icons:** `lucide-react`, imported individually. Icon-only buttons (`size="icon"`) need `aria-label` or visually hidden text; decorative icons get `aria-hidden`.
- **Don't break Radix accessibility:** keep `DialogTitle`/`DialogDescription` (use `sr-only` if visually hidden), use `asChild` instead of nesting buttons, and don't remove focus rings (`focus-visible:ring-*`).
- **Updating components:** re-running `shadcn add --overwrite` replaces our customizations. Only do it deliberately, then review the diff and re-apply our variants.

## TanStack Router rules

- **File-based routes** in `src/routes/`. `routeTree.gen.ts` is generated; never edit it.
- **Router context** provides `queryClient` and `auth`. Declare it with `createRootRouteWithContext`.
- **Auth guard:** `_app.tsx` runs `beforeLoad` → `context.queryClient.ensureQueryData(meQueryOptions)`; on 401, `throw redirect({ to: '/sign-in', search: { redirect: location.href } })`.
- **Data loading:** loaders call `context.queryClient.ensureQueryData(...)` with `queryOptions` exported from the feature's `api.ts`; components read with `useSuspenseQuery` using the same options. Never fetch in loaders without going through TanStack Query.
- **Search params** are validated with `validateSearch` (Zod). Examples: `sign-in` takes `redirect?` (same-origin path only) and `login?: 'failed'`.
- **Navigation** only through typed `Link`, `useNavigate`, and `redirect`. No string-built URLs, no `window.location` except the Steam sign-in link.
- **Errors:** each layout route defines `errorComponent` and `notFoundComponent`. A 404 from the API in a room loader throws `notFound()`, showing the same "room not available" screen for non-members and missing rooms.
- **Pending UI:** use `pendingComponent` with shadcn `Skeleton`s for route-level loading.
- Set `defaultPreload: 'intent'` on the router; loaders must be safe to run on hover.

## The contract with hideout-api

- `src/lib/api/schema.d.ts` is generated. Never edit it. Never hand-write request/response types that duplicate it.
- All HTTP calls go through `src/lib/api/client.ts` (`openapi-fetch`, `credentials: 'include'`, typed errors).
- If a feature needs an endpoint or field that isn't in the contract, **stop and write it up** as a request for hideout-api (method, path, request, response, error codes, why). Don't invent the shape.
- Supabase Realtime `messages` rows are also part of the contract. Their type lives in `src/features/messages/types.ts` and every payload is parsed with Zod so schema drift fails loudly.
- After `npm run gen:api`, run typecheck. Type errors mean the contract changed; fix call sites, don't cast around them.

## Talking to the API

- Dev: the Vite proxy forwards `/api` to `http://localhost:3001`, so it's same-origin and cookies just work.
- Prod: the API is on a same-site subdomain (e.g. web `app.hideout.gg`, API `api.hideout.gg`). `VITE_API_URL` points at it. Requests use `credentials: 'include'`.
- If auth works in dev but not prod, check the domains are same-site before touching code. Different registrable domains make the session cookie third-party and browsers block it.
- Session flow: `GET /api/auth/me` (via `meQueryOptions`) decides signed in vs. not. The "Sign in with Steam" button is a plain anchor to `${API_URL}/api/auth/steam`. After Steam, the API redirects back; `?login=failed` shows the retry state.

## Environment

Read env only through `src/lib/env.ts` (Zod-validated `import.meta.env`). Allowed variables: `VITE_API_URL`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Everything with `VITE_` ships to browsers, so **no secrets ever** in this repo. The LiveKit URL comes from the voice-token response, not env.

## Realtime, voice, and content rules

- **Supabase:** one client in `lib/supabase.ts`, authenticated with the token from `GET /api/auth/realtime-token`, refreshed before `expiresAt` (update Realtime with `supabase.realtime.setAuth`). Never call `.insert/.update/.delete/.rpc` from the browser; writes go through the API.
- **Realtime:** one subscription per open text channel, created in a hook and removed in cleanup. After reconnect, fetch messages newer than the last one held. Deduplicate by id.
- **Messages:** optimistic send with a temp id, reconciled by the realtime insert; failed sends show a retry action. Send an `Idempotency-Key` per message.
- **Voice:** one LiveKit `Room` in the voice store, surviving route changes. Fresh token per join. Explicit states for mic permission, denied, connecting, connected, reconnecting, disconnected, kicked.
- **User content:** never `dangerouslySetInnerHTML`. Linkify safely; links get `rel="noopener noreferrer nofollow"` and `target="_blank"`.

## UI quality bar

- Every async view handles loading, empty, error, and offline states. Error copy says what happened and what to do.
- Keyboard accessible: visible focus (`focus-visible` rings stay on), Esc closes modals and drawers, focus returns to the trigger, logical tab order through composer and voice controls. `aria-live` for new messages and connection banners.
- Respect `prefers-reduced-motion` (`motion-safe:` / `motion-reduce:` on animations, including `tw-animate-css` classes) and both themes.
- Virtualize lists over ~200 items (messages, members).
- Lighthouse accessibility score ≥ 95 on main screens.

## Conventions

- Typed function components, named exports, one component per file. No `any` without a comment. Conventional Commits. No new dependency without saying why; check shadcn, Radix, and TanStack first.
